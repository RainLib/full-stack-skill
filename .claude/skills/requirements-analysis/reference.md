# 需求分析参考指南

## 用户故事编写规范

### 格式

```
As a <角色>
I want <目标/行为>
So that <价值/原因>
```

### 好的用户故事特征（INVEST）

| 特征 | 含义 | 检查问题 |
|------|------|----------|
| **I**ndependent | 尽量独立 | 能否单独交付？ |
| **N**egotiable | 可协商 | 是否有讨论空间？ |
| **V**aluable | 有价值 | 用户能获得什么？ |
| **E**stimable | 可估算 | 能否估算工作量？ |
| **S**mall | 足够小 | 一个迭代内能完成？ |
| **T**estable | 可测试 | 有明确的验收标准？ |

## 验收标准编写规范

### Given-When-Then 格式

```
Given <前置条件/上下文>
When  <触发动作>
Then  <预期结果>
```

### 常见验收标准类型

- **正常路径**：预期操作下的标准行为
- **边界条件**：空输入、最大长度、极值
- **异常路径**：权限不足、网络断开、数据冲突
- **性能约束**：响应时间、并发数

## 优先级定义

| 优先级 | 含义 | 标准 |
|--------|------|------|
| P0 | 必须有 | 缺失则产品不可用 |
| P1 | 应该有 | 影响用户体验但有替代方案 |
| P2 | 可以有 | 锦上添花，后续迭代可加 |

## 常见追问清单

### 用户与角色

- 系统有多少种用户角色？
- 未登录用户能看到什么？
- 角色权限是否可配置？

### 业务流程

- 核心流程有几个步骤？
- 每个步骤的前置条件是什么？
- 异常情况如何处理（回退/重试/告警）？

### 数据

- 数据量预估（初期/半年/一年后）？
- 是否有数据迁移需求？
- 敏感数据如何处理（加密/脱敏）？

### 非功能

- 目标用户群体规模？
- 并发用户数预估？
- 是否有合规要求（GDPR / 等保）？
- 可用性目标（99.9% / 99.99%）？

## 需求分析常见陷阱

1. **过早设计**：需求阶段不要涉及具体技术实现
2. **遗漏异常流程**：只写了正常路径，忽略了错误和边界
3. **角色模糊**：没有明确区分不同用户的权限边界
4. **非功能缺失**：只关注功能，忽略性能、安全、兼容性
5. **假设未记录**：对模糊点做了假设但未写入"待澄清项"
